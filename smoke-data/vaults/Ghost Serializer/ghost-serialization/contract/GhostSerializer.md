# GhostSerializer

The interface every Ghost serializer implements, whether generated by the compiler or written by hand.

## What it is about

A `GhostSerializer<T>` knows how to read a `T` from JSON and write it back. The KSP processor generates one per `@GhostSerialization` class, and the built-in serializers for primitives, collections and protobuf types implement it too. `Ghost` and the HTTP integrations only ever talk to this interface.

## How it works

The interface has three kinds of members. Metadata: `typeName`, `isResilient` (skip instead of throw on bad collection items) and `isProto` (use the proto3 canonical JSON mapping). Reading: one `deserialize` overload for each input channel (an Okio `BufferedSource`, the streaming `GhostJsonReader`, the in-memory `GhostJsonFlatReader`, and the `GhostJsonStringReader`). Writing: `serialize` for an Okio `BufferedSink`, the byte `GhostJsonWriter` and the char `GhostJsonStringWriter`. `warmUp` is an optional hook for priming the JIT or ART.

The streaming and flat readers are intentionally kept as separate overloads instead of one abstraction, because unifying them would cost throughput on array-heavy payloads. `isProto` has `BINARY` retention semantics noted in the source: runtime dispatch (for example in Spring's message converter) checks it instead of the annotation.

## The code

```kotlin
interface GhostSerializer<T> {
    val typeName: String
    val isResilient: Boolean
    val isProto: Boolean
    fun deserialize(source: BufferedSource): T
    fun deserialize(reader: GhostJsonReader): T
    fun deserialize(reader: GhostJsonFlatReader): T
    fun deserialize(reader: GhostJsonStringReader): T

    fun serialize(sink: BufferedSink, value: T)
    fun serialize(writer: GhostJsonWriter, value: T)
    fun serialize(writer: GhostJsonStringWriter, value: T)

    fun warmUp()
}
```
