# GhostCodegenConstants

Constants for whole-file code generation: names of generated members, call templates, and the regexes that tidy generated source.

## What it is about

Where [[GhostEmitterConstants]] holds the snippets for the inside of `serialize` and `deserialize`, this object holds what shapes the generated file around them: the serializer class header, the `OPTIONS` tables, the warm-up code, the KDoc text and the cleanup of KotlinPoet's output. It sits in the codegen stage and is read by the code generator, the import resolver and the setup emitter.

## How it works

Everything is a `const val` (the one exception is a KotlinPoet `ClassName` for `okio.ByteString`). Some groups are worth knowing:

- **Reader and writer method names** (`beginObject`, `selectNameAndConsume`, `nextInt`, `nextULongOrNull`, `captureRawJson`, `decodeBase64String` ...). Code is emitted with `%L` placeholders, so the name of the runtime method that the generated serializer calls is changed in one place.
- **Naming prefixes** such as `H_` and `HS_` for hash constants, `OPTIONS_` and `ENUM_OPTIONS` for field-name option tables, `reader1` and `reader3` for warm-up readers.
- **Call-format templates** (`TEMPLATE_INVOKE_EMPTY`, `TEMPLATE_INVOKE_ONE`, ...) used with `COMPACT_CALL_MAX_INLINE_LENGTH = 80`: a call short enough stays on one line, a longer one is opened over several lines with one argument per line and a trailing comma.
- **Two cleanup regexes** that post-process the file text.

## The code

KotlinPoet always writes `public` when Kotlin's explicit API mode is on, which would clutter the output, so a regex removes it while keeping the indentation, and a second one drops redundant `import kotlin.X` lines:

```kotlin
const val REGEX_TRIM_REDUNDANT_PUBLIC =
    """^(\s*)public (?=object |class |interface |fun |val |var |override |companion |data |enum |suspend |inline |operator |expect |actual )"""

/** Replacement for [REGEX_TRIM_REDUNDANT_PUBLIC]: keep the leading indent capture group. */
const val STR_REGEX_GROUP_1 = $$"$1"
```

The multiline templates show the shape of generated calls:

```kotlin
const val TEMPLATE_INVOKE_OPEN = "%L(\n"
const val TEMPLATE_TYPED_OF_OPEN = "%T.of(\n"
const val TEMPLATE_ARG_LINE = "%L,\n"
const val TEMPLATE_STRING_ARG_LINE = "%S,\n"
```

The generated KDoc comes from `STR_KDOC_SERIALIZER` ("Ghost serializer for [%T]") and `STR_KDOC_GENERATED` ("Generated by GhostSerialization. Do not modify manually."). The warm-up templates build a reader over a sample string and call `deserialize` in a `try` so a class loads early without failing the application.
